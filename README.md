# CookMate 5

Финальный Android-проект в формате offline-first mini-product.  
`CookMate5` развивает обычный клиент рецептов до приложения с личными данными пользователя, локальными сущностями, своими сценариями использования и фоновой синхронизацией.

## Что добавлено в финальной работе

Базовая часть сохранена:
- поиск рецептов;
- экран деталей;
- Navigation Compose;
- Retrofit;
- Room;
- Hilt;
- реактивное обновление UI через Flow / StateFlow / SharedFlow.

Новая продуктовая часть:
- экран `Опции`;
- экран `История`;
- персональный раздел `Книга`;
- собственные рецепты пользователя;
- личные заметки и рейтинг;
- список покупок;
- локальные коллекции;
- offline-first кэш;
- фоновая синхронизация через `WorkManager`.

## Какие пользовательские данные появились

В `Room` хранятся:
- `cached_meals` — локальный кэш рецептов и собственных рецептов;
- `recent_meals` — история открытий;
- `meal_collections` — пользовательские коллекции;
- `collection_meals` — связь many-to-many между коллекциями и рецептами;
- `meal_notes` — личные заметки и рейтинг;
- `favourite_meals` — избранные рецепты;
- `shopping_list_items` — список покупок.

В `DataStore` хранятся только настройки:
- `show_only_favorites`;
- `offline_only_mode`;
- `background_sync_enabled`;
- `history_limit`;
- `start_destination`.

## Новые законченные сценарии

### 1. Личная кулинарная книга
- пользователь создаёт коллекции;
- добавляет в них рецепты;
- закрепляет коллекции;
- редактирует название и описание;
- открывает коллекции офлайн.

Это отдельная локальная сущность и отдельная связь между сущностями.

### 2. Собственные рецепты
- пользователь создаёт свой рецепт локально;
- задаёт название, категорию, кухню, инструкцию, ингредиенты и URL обложки;
- редактирует и удаляет свой рецепт;
- свой рецепт живёт отдельно от API-контента;
- свой рецепт не обязан быть в избранном.

### 3. Личные заметки и рейтинг
- в деталке можно поставить рейтинг;
- сохранить свою заметку;
- заметки и оценка отображаются в книге, истории и деталке;
- данные переживают перезапуск.

### 4. Список покупок
- ингредиенты можно перенести из деталки рецепта;
- можно добавлять позиции вручную;
- одинаковые позиции объединяются;
- купленные позиции можно отмечать;
- список можно очистить частично или полностью;
- весь сценарий работает офлайн.

### 5. История использования
- каждый открытый рецепт попадает в историю;
- история читается из Room;
- по ней можно быстро вернуться к уже сохранённым рецептам без сети.

### 6. Offline-first поиск и доступ к данным
- поиск работает по локальному кэшу и обновляет его через сеть;
- деталка сначала показывает кэш, потом обновляется;
- коллекции, заметки, покупки, история и свои рецепты читаются из Room;
- в offline-only режиме приложение остаётся полезным без сети.

### 7. Фоновая актуализация сохранённых рецептов
- `WorkManager` обновляет уже сохранённые рецепты;
- источники для синхронизации: избранное, коллекции, история;
- пользователь может вручную запустить синхронизацию из опций.

## Как устроена offline-first часть

Основной принцип: UI работает с локальными данными напрямую, а сеть нужна для обновления и синхронизации.

- поиск использует `cached_meals`;
- деталка сначала читает локальный рецепт, затем пробует обновить его из API;
- история, коллекции, заметки, избранное, свои рецепты и покупки читаются из Room;
- настройки читаются из DataStore;
- при отсутствии сети приложение остаётся рабочим на уже сохранённых данных.

## Где и зачем используется WorkManager

`SavedMealsSyncWorker`:
- запускается в фоне;
- собирает ids рецептов из избранного, коллекций и истории;
- загружает свежие версии через API;
- обновляет локальный кэш;
- помогает держать офлайн-данные актуальными.

Кнопка `Синхронизация сейчас` в опциях запускает тот же сценарий вручную.

## Какие тесты написаны

1. `DiscoverFeedReducerTest`
- экранная логика поиска;
- пустой запрос;
- фильтр по избранному;
- ошибка без кэша.

2. `SyncTargetSelectorTest`
- отбор рецептов для синхронизации;
- приоритет: избранное -> коллекции -> история;
- удаление дублей;
- ограничение числа целей.

3. `SavedMealsSyncUseCaseTest`
- логика фоновой и ручной синхронизации;
- успешный sync;
- частичный fail;
- пустой набор целей.

4. `CustomMealEditorTest`
- создание собственного рецепта;
- обновление собственного рецепта;
- парсинг ингредиентов;
- валидация данных.

5. `ShoppingListServiceTest`
- добавление ингредиентов из рецепта;
- объединение одинаковых позиций;
- ручное добавление;
- очистка checked-позиций;
- полная очистка списка.

## Как проверить вручную

1. Найти рецепт через `Поиск`.
2. Открыть деталку и добавить рецепт в избранное.
3. Создать коллекцию в `Книге`.
4. Добавить рецепт в коллекцию.
5. Создать свой рецепт.
6. Отредактировать свой рецепт.
7. Поставить рейтинг и сохранить заметку.
8. Добавить ингредиенты в `Покупки`.
9. Добавить ручную позицию в `Покупки`.
10. Очистить купленные и затем полностью очистить список.
11. Открыть `История` и убедиться, что недавно просмотренные рецепты сохранены.
12. Перезапустить приложение и проверить восстановление коллекций, заметок, истории, покупок и стартового экрана.
13. Включить offline-only режим и проверить доступ к уже сохранённым данным без сети.
